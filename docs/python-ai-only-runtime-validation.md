日期：2026-11-23。此记录补充首次迁移报告，不将历史验收当成本次结果。

## 根因与配置处理

- 迁移版私有 `.env` 使用示例模型密钥；同一供应商的 `/models` 鉴权检查，原配置返回 200，迁移版原配置返回 401。类型路由前的输入审核因此报服务不可用，对外表现为 `/internal/v1/route` 503。
- 迁移版 PostgreSQL 地址为 `host.docker.internal`，宿主机直启连接超时；原配置的有效地址为 `localhost`，执行 `SELECT 1` 成功。这与模型鉴权失败是两个独立原因。
- 已备份迁移版私有配置至忽略目录 `target/config-backup/`，完整复用原项目 `ai-service/.env`。Spring 复用原业务配置，去除旧 `langchain4j` / `dashscope` 配置，显式统一 `ai.token` 与 Python 双向令牌，服务地址为 `http://localhost:8000`。
- 已比对 Python 配置完全一致、Spring 业务配置一致、三处令牌一致。私有配置和备份不进入 Git；原项目未修改。输入审核、checkpoint 和客服重排未被关闭。
- 公开 `.env.example` 改用宿主机直启地址，两个令牌使用同一占位说明；README 补充原配置复用与故障定位。容器启动需自行使用容器可达地址，不能直接沿用宿主机 localhost。
