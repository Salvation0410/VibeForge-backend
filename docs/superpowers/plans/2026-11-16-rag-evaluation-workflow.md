# RAG 分层评估流程实施计划

本轮依据用户提供的 Datawhale《RAG系统评估》章节及已批准的 2026-11-13 方案，先实现独立评估设施，生产检索和版本协议的候选修改单独交审。

目标：在当前公共知识快照上，区分上下文相关性、忠实度、答案相关性，增加可核对的证据标注和边界测试，形成能复现、能归因、有预算的对照流程。

## 执行步骤

- [x] 扩充独立版本评测集至48题，保留旧90题和11月13日数据，逐事实记录原文span及来源；标记代理标注待人工审核，诊断集不冒充盲测集。
- [x] 新增纯本地校验、块级IR指标、必要证据覆盖、缺失/错误计数及分组聚合工具；语义评分不使用字符串匹配冒充。
- [x] 新增显式启用的真实模型快照对照：精确cosine取Top8、真实BGE重排，两策略共享候选/顺序，使用生产字符和字节预算；最多三块不变。

文件划分：`rag_evaluation_workflow.py`负责数据校验和确定性度量，`rag_snapshot_experiment.py`负责只读快照实验及调用额度，`rag_evaluation_judge.py`负责可选语义评审契约；对应测试位于`ai-service/tests/`。评测集位于`ai-service/evaluation/`，不上传到公共知识库。生产`customer_service_rag.py`、版本任务与数据库结构本轮不修改。
