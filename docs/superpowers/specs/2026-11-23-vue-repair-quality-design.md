# Vue 修复读取循环与功能接线优化

## 证据与目标

2026-11-23 的请求首次缺少 HeroSection 必填属性；修复一次后进入质量审查，第二次修复发生 17 次读取和 2 次写入，最终共享工具数 40、修复数 2，质量仍拒绝。当前源码存在 ProductCard/ProductGrid/App 事件名称不一致及未接通的导航。Reviewer 理由正文已无持久记录，静态源码发现不等同于历史四条拒绝理由。

## 方案与边界

采用有限纠偏、静态契约与脱敏观测组合。直接扩容会增加无效读取成本；仅改提示无法约束循环；直接停止首次重复会误伤必要的依赖探索。因此正式 Vue 修复在首次成功写入前，连续四次同路径同内容完整重读后给出一次固定纠偏，再持续四次无新增信息则以 VUE_REPAIR_READ_STALLED 失败。新内容/路径、非读取、未知/截断结果重置连续数；纠偏机会每阶段一次，恢复保留。工具实际执行并照常计费，不缓存读取，不直接交回验证冒充新候选。已写入阶段沿用原保护。

生成和修复提示补充完整事件调用链与导航目标核对。新增可信脚本 --events 模式：只检查静态本地组件显式运行时 defineEmits 声明和父级字面自定义事件监听。仅在可证明关闭原生属性透传的组件上阻断未知自定义事件；默认透传、原生事件、动态/类型/展开、attrs 转发、未知组件和扫描不完整保守跳过。默认透传组件的疑似错接仅形成有限审查提示，不能据此作不存在证明。VUE_EVENT_CONTRACT_FAILED 进入原修复，VUE_EVENT_CHECK_UNAVAILABLE 直接失败。不得要求所有已声明事件都有监听，也不得据此宣称完整事件/浏览器验证。

构建返回组合检查摘要，分别标明必填属性、事件覆盖和锚点跳过原因。每轮校验/构建/审查在验证子图保存有界固定字段记录，经两次白名单投影进入现有 JSONB 状态摘要；Vue 工具阶段日志记录固定原因与读写/重复读取计数。诊断不进入模型、父图或公共事件；审查提示只包含限定的静态契约事实并与诊断分开。终态清理 checkpoint 后摘要在原 TTL 内保留，无 schema 迁移。

默认两次修复、40 次模型工具调用保持。构建/质量预算拆分和真实生成效果比较留待下一轮；不新增 Java AI 执行、Vue 回滚或自动恢复。
