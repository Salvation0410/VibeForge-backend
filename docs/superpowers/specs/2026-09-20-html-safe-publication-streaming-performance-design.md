# HTML 安全发布与流式页面性能治理方案设计

## 1. 文档状态

- 日期：2026-09-20
- 状态：待评审
- 适用范围：`HTML` 单文件生成链路、生成工作台流式交互和本地预览
- 前置方案：`docs/superpowers/specs/2026-09-20-ai-multifile-safe-generation-design.md`
- 事故样本：应用 `459157197728309248`

本文定义单 HTML 候选从模型输出到正式预览版本的完整性门禁，以及长代码流导致生成工作台失去响应的前端治理方案。本文是方案设计，不是实施计划；文件级改动、测试先后顺序和提交拆分将在本文确认后另行编写。

## 2. 事故证据与根因

### 2.1 当前活动 HTML 是截断产物

事故文件 `tmp/code_output/html_459157197728309248/index.html` 具有以下确定性特征：

- 文件以自然语言说明和未闭合的 Markdown `html` 围栏开头。
- 文件在 JavaScript 模板表达式 `${escapeText` 中间结束。
- 缺少 `</script>`、`</body>` 和 `</html>`。
- `div` 开闭数量不一致。
- 页面初始 DOM 使用骨架屏，真实内容依赖 JavaScript 替换；脚本无法解析后骨架屏永久保留。

因此“新版应用无法完整渲染”不是图片加载慢或浏览器缓存，而是不完整 HTML 被发布为当前版本。

### 2.2 HTML 链路仍允许不完整候选覆盖正式文件

当前运行服务来自原工作区 `dev` 分支，默认 `AI_ENGINE=legacy`，尚未运行已完成的安全发布分支。旧链路存在四个缺口：

1. HTML 流结束后直接解析并覆盖 `html_<appId>/index.html`。
2. 解析器找不到闭合代码围栏时，把整个模型响应作为 HTML 返回。
3. 保存异常在 `doOnComplete` 中被捕获后只记录日志，不能阻止外部成功终态。
4. HTML 没有 release、活动指针和上一成功版本，覆盖后无法文件级回滚。

上一轮方案已保护 `MULTI_FILE`，但本事故应用被路由为 `HTML`，不能依赖多文件校验器间接兜底。

### 2.3 完整重写使模型截断概率升高

前端“优化提示”要求基于当前应用重新输出完整可运行代码。单文件同时包含 HTML、CSS、JavaScript，随迭代持续增长；每次小改仍要求全量重写，输出量容易达到模型上限。

提高模型输出 token 上限只能降低截断概率，不能提供正确性保证。无论结束原因为 `STOP` 还是供应商未正确返回结束原因，候选都必须通过确定性门禁后才能发布。

### 2.4 页面未响应是前端高频全量更新

当前每个 SSE 内容分片都会：

1. 拼接到不断增长的助手消息字符串。
2. 写入 Vue 响应式对象，使完整 `<pre>` 重新参与渲染。
3. 触发消息内容 watcher。
4. 执行一次 `nextTick` 和平滑滚动。

随着文本增长，字符串复制、DOM 文本更新、布局和滚动动画相互叠加。预览 iframe 同时加载旧页面，成功后又按六个延迟重复整页刷新，进一步占用主线程和网络。Chrome 的“页面无响应”是这组行为的叠加结果，而不是 SSE 连接本身失效。

## 3. 目标

1. 截断、Markdown 残留、结构缺失或脚本明显不完整的 HTML 不能成为活动版本。
2. HTML 生成失败时，预览、部署、下载继续读取上一成功版本。
3. `done` 只代表已经通过门禁并完成活动指针切换。
4. 长代码生成期间工作台保持可交互，用户可退出页面或取消生成。
5. 生成期间保留上一版预览，成功后只自动刷新一次。
6. Legacy 与 LangGraph 共用 Spring 的 HTML 校验和发布边界。
7. Spring 仍是业务文件唯一所有者；Python 不直接访问项目目录。
8. 新增或实质修改的核心方法使用中文注释说明职责和关键失败语义。

## 4. 非目标

- 不尝试自动续写和拼接已经截断的模型响应。
- 不通过简单追加闭合标签“修复”未知位置的截断代码。
- 不把 JavaScript 的任意运行时业务异常都视为发布失败。
- 不在本阶段引入通用在线 IDE 或完整 AST 增量编辑协议。
- 不恢复已被原地覆盖且不存在备份的文件；恢复只能使用聊天历史中可验证的完整候选。
- 不修改 Vue 项目构建协议，Vue 仅复用前端流式性能优化。

## 5. 方案选择

### 5.1 方案 A：只提高 token 上限并收紧提示词

改动最小，但无法防止网络中断、供应商结束原因异常、Markdown 格式错误或脚本结构损坏。该方案只能作为降低失败率的辅助措施，不能作为发布安全方案。

### 5.2 方案 B：保存前校验，继续覆盖平铺文件

能够拦截已知截断形态，但写入或进程故障仍可能破坏正式文件，也无法稳定回滚。它解决“是否有效”，没有解决“如何提交”。

### 5.3 方案 C：严格门禁、不可变版本发布和前端批处理

候选先经过结束原因检查、严格解析、确定性校验和受限浏览器烟测，再写入不可变 release 并原子切换活动指针。前端对内容分片做批处理，只显示生成状态而不逐 token 重绘完整源码。

本设计选择方案 C。它复用已实现的多文件版本基础设施，能够同时关闭坏文件覆盖和页面无响应两个问题，且不把正确性寄托在模型配置上。

## 6. 总体架构

```text
模型输出
  -> 收集候选文本与 finishReason
  -> HtmlArtifactParser 严格提取单一 HTML 文档
  -> HtmlArtifactValidator 确定性校验
  -> HtmlPreviewSmokeTester 受限浏览器烟测
  -> ArtifactPublicationService.publishHtml
       -> .staging/<requestId>
       -> 磁盘重读与 hash 核对
       -> .releases/<requestId>
       -> 原子替换 .current
  -> 内部 completed
  -> 对外 SSE done

生成工作台
  -> SSE 分片进入非响应式缓冲区
  -> 按帧/固定间隔更新轻量进度
  -> 成功终态重新获取应用信息
  -> 只加载一次 .current 指向的新版本
```

核心组件：

| 组件 | 职责 | 失败语义 |
| --- | --- | --- |
| `HtmlArtifactParser` | 严格提取唯一完整 HTML 文档 | 返回 `HTML_FORMAT_INVALID`，不产生部分结果 |
| `HtmlArtifactValidator` | 检查文档、CSS、JavaScript 和 Markdown 残留 | 返回全部确定性错误，不写文件 |
| `HtmlPreviewSmokeTester` | 在候选 release 上检测加载和脚本启动错误 | 超时或语法错误拒绝发布 |
| `ArtifactPublicationService` | 写入不可变 HTML release 并切换指针 | 任一步失败保留旧 `.current` |
| `ArtifactPathResolver` | 统一解析 HTML/MULTI_FILE/Vue 活动根目录 | 指针损坏时使用明确的兼容回退 |
| 前端流缓冲器 | 合并高频内容事件并更新进度 | UI 卸载或取消时清理定时器和连接 |

## 7. HTML 输出协议

### 7.1 推荐协议

系统提示改为只允许以下内容：

````text
```html
<!doctype html>
<html lang="...">
  ...
</html>
```
````

围栏外不得出现标题、说明、总结或其他字符。只能有一个 HTML 区块，区块必须闭合，正文必须非空。

### 7.2 兼容纯 HTML

为了兼容供应商偶尔忽略 Markdown 围栏，解析器可以接受以 `<!doctype html>` 或 `<html` 开始、以 `</html>` 结束的纯 HTML。纯 HTML 前后只允许空白，不允许自然语言前缀。

除上述两种结构外全部拒绝。特别禁止旧逻辑中的“围栏未闭合则保存整个响应”。

### 7.3 模型结束原因

- `LENGTH`、`MAX_TOKENS`：返回 `MODEL_OUTPUT_TRUNCATED`。
- `CONTENT_FILTER`、`CONTENT_FILTERED`：返回 `MODEL_OUTPUT_BLOCKED`。
- `STOP`：允许进入解析和校验，但不自动判定有效。
- `null` 或未知值：记录告警，仍执行所有硬校验和烟测。

## 8. 确定性 HTML 校验

校验器一次收集所有错误，至少覆盖：

### 8.1 文档完整性

- 包含唯一的 `doctype`、`html`、`head` 和 `body` 主结构。
- `html/head/body/style/script` 必须具有必要闭合标记。
- 不含 Markdown 围栏、围栏外说明或模型结束残片。
- 不含 NUL 等不允许的控制字符。
- 文件结尾必须是 `</html>`，其后只允许空白。

HTML 容错解析器会自动补标签，不能只依赖解析后的 DOM。校验必须同时检查原始文本边界和解析后的结构。

### 8.2 内联 CSS

- `<style>` 区块必须闭合。
- 去除注释和字符串后，花括号必须平衡。
- 不允许内容截断在 CSS 声明、注释或字符串内部。

### 8.3 内联 JavaScript

- `<script>` 区块必须闭合。
- 忽略字符串、模板字符串、正则字面量和注释后，圆括号、方括号和花括号必须平衡。
- 模板字符串中的 `${...}` 必须闭合。
- 不允许结尾为明显未完成的成员访问、赋值、模板表达式或关键字结构。

确定性扫描器只负责发现明确不完整，不替代真正的 JavaScript 引擎；可执行性由烟测补充验证。

## 9. 受限浏览器烟测

### 9.1 运行方式

候选通过静态校验后，Spring 将其写入 staging，并通过现有 Selenium/WebDriver 基础设施打开仅供内部访问的候选 URL。页面加载最多等待 8 秒，随后观察 3 秒稳定窗口，单次烟测总计不得超过 12 秒。浏览器禁用下载、弹窗和页面跳出，并收集：

- 页面加载错误。
- JavaScript 未捕获异常和语法错误。
- 主文档是否产生可见内容。
- 初始骨架节点是否在稳定窗口后仍覆盖主要内容。

### 9.2 发布判定

以下情况拒绝发布：

- JavaScript 解析错误。
- 页面加载超时且主文档未进入可用状态。
- body 为空或仅剩约定的 skeleton/loading 占位节点。
- 页面执行导致顶层导航离开候选预览地址。

外部图片、字体或第三方接口失败只记录告警，不作为硬失败条件，避免本地网络波动误伤静态页面。

烟测能力不可用时默认拒绝新的 HTML 发布并返回 `HTML_SMOKE_TEST_UNAVAILABLE`。这是有意的安全失败；不能在无法验证时覆盖上一成功版本。可通过显式开发配置降级为“仅静态校验”，生产环境禁止降级。

## 10. HTML 版本化发布

### 10.1 目录结构

```text
tmp/code_output/html_<appId>/
  .current
  .publication-sequence
  .published/
    <requestId>.json
  .releases/
    <requestId>/
      index.html
      manifest.json
  .staging/
    <requestId>/
      index.html
      manifest.json
```

HTML 与 MULTI_FILE 使用相同的 requestId 墓碑、单调发布序号、hash 冲突检查和“当前版本加最近两个成功实体版本”保留策略。

### 10.2 发布顺序

1. 校验请求 ID、生成租约和取消/提交状态。
2. 解析并执行确定性校验。
3. 写入 staging，重读 `index.html` 并核对 SHA-256。
4. 对 staging 执行浏览器烟测。
5. 原子移动到 `.releases/<requestId>`。
6. 写入永久发布墓碑。
7. 根据单调序号原子切换 `.current`。
8. 返回发布成功；随后执行不影响终态的旧版本清理。

同一 requestId 和相同 hash 为幂等成功；同一 requestId 不同 hash 返回 `ARTIFACT_VERSION_CONFLICT`。已经被保留策略清理的 requestId 不能重建或回滚。

### 10.3 读取兼容

预览、部署、下载和导出必须通过 `ArtifactPathResolver`：

1. 有有效 `.current` 时读取对应 HTML release。
2. 没有 `.current` 时兼容读取升级前平铺 `index.html`。
3. `.current` 损坏时恢复到序号最新且 manifest/hash 完整的 release。
4. 不把当前事故中的截断平铺文件自动归档为成功 release。

## 11. Legacy 与 LangGraph 集成

### 11.1 Legacy

HTML 生成必须使用可取得 `ChatResponse.finishReason` 的 `TokenStream`。完成回调内调用统一的 `publishHtml`，发布成功后才完成 Reactor 流；校验或发布异常必须进入错误通道，不能只记录日志。

Legacy 模型内容分片仍可用于内部采集，但前端展示不再依赖每个源码 token。

### 11.2 LangGraph

HTML 分支在确定性校验后调用 Spring `artifact_publish`，参数携带 `codeGenType=HTML`。Spring 必须重新解析、重新校验和烟测，不能信任 Python 先前的校验结果。

Python 收到 `published=true` 后才能发出 `completed`。发布响应不确定时继续复用相同 `toolCallId` 的有界重试语义。

## 12. 前端流式性能设计

### 12.1 不逐 token 展示完整源码

生成中的源码写入普通字符串缓冲区，不直接写入 Vue 响应式消息。UI 只展示：

- 当前阶段，例如“正在生成”“正在校验”“正在发布”。
- 已接收字符数。
- 持续时间。
- 取消生成操作。

为保持现有 SSE 兼容，后端内容事件可以继续发送；前端使用 80ms 固定批处理窗口，每个窗口最多提交一次轻量状态更新。生成期间不展示原始源码或尾部源码摘要。最终成功后从聊天历史重新加载正式 AI 消息；完整代码通过下载功能访问。

### 12.2 滚动治理

- 流式期间最多每 200ms 自动滚动一次。
- 流式更新使用 `behavior: auto`，避免叠加平滑滚动动画。
- 用户主动向上滚动后暂停自动跟随，直到用户回到底部。
- 页面卸载、终态或取消时清理所有定时器和动画帧。

### 12.3 预览刷新

- 生成开始时保留现有 iframe，不重新获取旧版文档。
- 使用遮罩提示“正在生成新版本”，但旧版仍可见。
- 只有收到 `done` 且重新获取应用详情后，加载一次新 `.current`。
- 移除 600ms 至 12s 的六次定时刷新。
- 加载失败时继续显示旧 srcdoc，并展示可重试错误；不得用 meta refresh 无限跳转。

### 12.4 取消与异常

生成按钮在活动期间变为“停止生成”。用户取消后保持上一版预览，并等待后端明确的取消终态。`MODEL_OUTPUT_TRUNCATED`、`HTML_FORMAT_INVALID`、`HTML_VALIDATION_FAILED` 和 `HTML_SMOKE_TEST_FAILED` 使用可理解的中文提示，同时显示 requestId 便于排查。

## 13. 优化提示与路由策略

“优化提示”按当前应用的 `codeGenType` 生成，不再对三种工程使用同一句泛化文案，也不重复注入角色设定。

HTML 模板：

```text
请基于当前应用的完整代码优化页面。必须保留现有业务功能、数据内容和交互逻辑，只调整信息层级、排版、间距、配色、响应式表现和必要的操作反馈；不要新增与需求无关的模块、加载动画或模拟数据。请返回修改后的完整单文件 HTML，CSS 和 JavaScript 必须内联且结构完整。最终回复只能包含一个闭合的 html 代码块，代码块外不得输出标题、解释或总结；无法完整输出时不要提交部分代码。
```

MULTI_FILE 模板：

```text
请基于当前应用的完整代码优化页面。必须保留现有业务功能、数据内容和交互逻辑，只调整信息层级、排版、间距、配色、响应式表现和必要的操作反馈；不要新增与需求无关的模块、加载动画或模拟数据。请返回完整的 index.html、style.css 和 script.js，三个文件必须相互匹配且可直接运行。严格按当前三文件协议输出，围栏外不得输出标题、解释或总结；无法完整输出时不要提交部分代码。
```

VUE_PROJECT 模板：

```text
请在当前 Vue 工程内优化页面。必须保留现有路由、组件职责、业务功能、数据内容和交互逻辑，只修改完成本次视觉与体验优化所必需的文件；不要重建工程、替换技术栈、引入无关依赖、模块、动画或模拟数据。优先复用现有组件和样式约定，确保修改后项目能够正常构建，并完整完成所有必要文件修改。
```

三套模板都强调最小范围修改和完整产物，避免“补全所有加载、空状态和动画”诱导模型无边界扩写。系统提示仍是最终输出协议的权威来源，前端模板只是本次优化意图，不能替代后端门禁。

当估算的现有 HTML 与预计修改输出接近模型安全输出预算时，不再继续单 HTML 全量重写。系统应返回 `HTML_OUTPUT_BUDGET_EXCEEDED`，建议用户将应用迁移为 MULTI_FILE，而不是冒险生成。P0 不自动迁移已有应用类型，避免路径和部署语义暗中变化。

## 14. 错误码与终态

| 错误码 | 含义 | 是否保留旧版本 |
| --- | --- | --- |
| `MODEL_OUTPUT_TRUNCATED` | 模型达到输出上限 | 是 |
| `MODEL_OUTPUT_BLOCKED` | 模型被内容策略中止 | 是 |
| `HTML_FORMAT_INVALID` | 输出协议或 Markdown 围栏错误 | 是 |
| `HTML_VALIDATION_FAILED` | HTML/CSS/JS 确定性校验失败 | 是 |
| `HTML_SMOKE_TEST_FAILED` | 候选浏览器烟测失败 | 是 |
| `HTML_SMOKE_TEST_UNAVAILABLE` | 强制烟测环境不可用 | 是 |
| `HTML_OUTPUT_BUDGET_EXCEEDED` | 单文件已不适合安全全量重写 | 是 |
| `ARTIFACT_PUBLISH_FAILED` | 文件或指针提交失败 | 是 |

失败流只能发出一个命名 `business-error` 事件，不能再发送 `done`。不使用 EventSource 保留的原生 `error` 事件承载业务 JSON；原生 `error` 只表示网络或协议故障。成功流只有 `.current` 切换后才能发送一个 `done`。

## 15. 事故应用恢复

应用 `459157197728309248` 当前平铺文件不得直接成为首个 release。恢复流程为：

1. 从聊天历史查找上一条完整 AI HTML 候选。
2. 使用新 parser、validator 和 smoke tester 离线验证。
3. 验证通过后，以新的恢复 requestId 发布为首个不可变 release。
4. 如果聊天历史没有完整候选，则保留损坏文件用于取证，并要求用户从原始需求重新生成。

恢复操作必须显式执行并记录来源，不能在服务启动时静默修改用户应用。

## 16. 测试策略

### 16.1 Java 单元与集成测试

- 严格 HTML parser：完整围栏、纯 HTML、自然语言前缀、未闭合围栏、重复区块和事故截断样本。
- HTML validator：结构闭合、CSS 注释/字符串、JavaScript 模板字符串、注释、正则和不平衡分隔符。
- 发布：首次发布、幂等、hash 冲突、指针失败、烟测失败、保留策略和旧 requestId 重放。
- 读取：`.current`、平铺兼容、损坏指针恢复、预览/部署/下载一致性。
- Legacy：`LENGTH` 不发布，`STOP` 但结构损坏不发布，成功发布后才完成。
- SSE：成功单 `done`，失败单 `error`，错误码和 requestId 完整。

### 16.2 浏览器烟测测试

- 完整静态页面通过。
- JavaScript 语法错误失败。
- 永久 skeleton 页面失败。
- 外部图片 404 只告警。
- 候选顶层跳转失败。
- WebDriver 不可用时生产配置安全失败。

### 16.3 前端测试

- 高频 10,000 个分片不会触发 10,000 次响应式消息更新。
- 流式期间不创建预览重载定时器。
- 成功后预览只刷新一次。
- 失败和取消保留旧 srcdoc。
- 自动滚动节流，用户离开底部后停止跟随。
- 组件卸载后 EventSource、timer 和 animation frame 均被清理。

### 16.4 手工验收

使用接近事故大小的 HTML 连续执行三轮优化：

1. 页面在生成期间可滚动、输入和点击停止。
2. 旧预览持续可见，没有反复白屏。
3. 模拟截断后收到明确错误，旧版本 hash 与 `.current` 不变。
4. 完整候选成功后只刷新一次并可正常交互。
5. 新窗口预览、部署和下载读取相同版本。

## 17. 可观测性

结构化日志记录 `requestId`、`appId`、生成类型、引擎、finishReason、候选字符数、校验错误码、烟测结果、发布序号和终态。禁止记录完整代码、完整提示词、令牌或会话信息。

建议指标：

- HTML 截断率。
- 各校验错误码计数。
- 烟测耗时与失败率。
- 发布成功率和指针恢复次数。
- 前端分片数、批量提交次数和生成期间 long task 次数。

## 18. 发布与回滚

1. 先合并并部署上一轮通用安全发布分支，确认运行 classpath 来自新提交。
2. 启用 HTML 静态门禁和版本发布，但暂不开启自动历史恢复。
3. 在开发环境验证浏览器烟测后，再在生产配置强制开启。
4. 发布前端流缓冲和单次预览刷新。
5. 最后人工恢复事故应用。

回滚应用代码时不得删除 `.releases`、`.published` 或 `.current`。旧程序仍可通过平铺兼容路径运行，但回滚期间禁止新的 HTML 生成，避免新旧写入协议同时修改同一应用目录。

## 19. 验收标准

- 事故截断样本稳定返回失败且不会改变活动版本。
- `LENGTH`、未闭合围栏和脚本语法错误均无法发布。
- 任一校验、烟测、写入或指针切换失败后，上一版本仍可预览、部署和下载。
- 只有发布成功才出现 SSE `done`。
- 30 KB 以上候选高频流式传输时，工作台没有持续主线程卡死或浏览器“页面无响应”。
- 生成期间不刷新 iframe，成功后只刷新一次。
- Legacy 与 LangGraph 使用相同的 Spring HTML 发布边界。
- 原工作区用户修改和 `projects/` 不被触碰。
