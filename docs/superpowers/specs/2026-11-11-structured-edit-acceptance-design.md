# 结构化编辑真实验收设计

用户已授权三类应用验收、最多 60 次供应商调用（审核、路由、生成、修复及失败调用均计入），新建专用测试应用，不部署到公网。继续当前 dev 工作区；保留前端既有客服改动。

采用独立本地验收代理限制实际 HTTP 供应商请求，避免只统计工作流轮次而漏掉 SDK 重试。代理仅显式 execute 启动、固定回环监听、固定上游和随机本地令牌；发送前持久化占用次数，断线和失败不退额度，不自动重试；达到 60 次拒绝转发。账本不保存提示词、源码、凭据或上游错误正文。验证并发和流式关闭后才执行真实调用。

专用测试账号经现有注册/登录接口建立会话；三类应用分别通过正常创建、生成和结构化修改入口操作，不改现有应用。每类依次检查四属性；固定业务内容包含标题、图片、按钮计数操作，浏览器比较修改前后内容、图片、计算样式和点击行为。记录 SSE 终态、任务状态、准备诊断及实际调用数。预算不足或环境失败时保留已取得证据，明确未覆盖项，不自动增加额度。

按观察到的失败进行最小代码优化并回归；没有证据时不扩大属性白名单、不推广 conservative。失败和取消场景用隔离测试应用验证；区分后端版本保留与浏览器旧预览保留，不能把 Vue 的可变工程当作不可变版本。截图/原始报告放忽略目录，提交工具、必要测试和中文交接结果。

备选是只完善离线工具或先验收 HTML，用户选择了完整三类型；真实调用代理属于验收设施，不进入生产请求路径。

实际执行记录（2026-11-11）：供应商账本到 60 后停止，未补齐全部属性。Vue 初始产物改为手写固定夹具，经 Spring 内部工具写入和构建；其颜色修改才使用真实模型。Chrome 调试端口方案被自动审批拒绝，实际采用无调试端口的 headless DOM 与截图检查。失败期间发现 PostgreSQL 状态投影缺少准备诊断和历史修改混入当前单属性修改，分别修复状态白名单、补充固定审查日志和有版本的范围规则。范围规则的最后复测因审查拒绝和额度拦截未获成功证据。以 `doc/generation-structured-edit-acceptance-handoff.md` 的结果矩阵及未覆盖项为准，不把原设计目标描述为已全部验收通过。
