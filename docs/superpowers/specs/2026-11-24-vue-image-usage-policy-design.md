# Vue 默认配图导致后台生成失败：已确认修复方案

## 问题与本轮证据

- 请求：`1ef4e814-e402-45d4-9cc0-f0c768f3424d`，应用：`482744429714173952`。
- 经 Spring 应用查询接口读取的初始需求是“做一个电商运营后台，看订单和销售数据”，未明确要求新增图片。
- Redis 工具成功缓存显示 `artifact_context.exists=false`，上下文准备自动搜索得到六张图片，主要涉及办公、分析看板等主题。
- 本轮通过 Spring `vue_source_snapshot` 只读取得 11 个文件，快照未截断，未发现图片 URL 或图片标签。没有修改生成项目。
- 工具缓存记录 39 次模型工具调用：15 次写入或修改、24 次读取。运行日志显示生成阶段最后连续返回无工具完成消息。
- PostgreSQL 摘要停留于 `generation_prepare`，没有验证历史；未据此声称源码已通过构建或质量审查。

## 触发与根因

`orchestration/nodes/input.py` 对未明确拒绝配图的首次 Vue 请求自动搜索图片。`vue_tool_loop.initial_progress` 又把任何非空 `imageAssets` 当作必须写入的资源。模型无工具结束时，若成功写入参数未包含资源 URL，则提醒最多两次，随后抛出 `VUE_IMAGE_USAGE_MISSING`。

这使平台主动提供的装饰素材成为后台、工具页面的硬性完成条件。当前系统提示也要求非空素材必须使用。此次失败的直接原因是确实未写入搜索图片，并非已写入 URL 被漏识别。

## 方案比较与推荐

1. **推荐：区分可选素材与明确配图要求。** 默认首次搜图保留为可选参考；只有 `requests_image_assets(prompt)` 识别到明确新增、替换、搜索或修复图片要求时强制使用。收益是无须按页面主题穷举例外，同时保留明确配图请求的失败检查；代价是默认搜图仍可能产生一次无用调用。
2. **按页面主题跳过搜图。** 增加后台、仪表盘、工具类关键词排除；可节省部分搜索，但规则容易误伤同时明确需要商品图片的后台，也会漏掉未知主题。
3. **所有搜索素材继续强制使用。** 增强提示让模型插入照片；保留原行为，但不能解决不需要图片的应用被装饰素材阻断的问题，不推荐。

## 推荐方案的实现范围

- 上下文新增明确的图片使用策略字段，保留原始 prompt、imageAssets 与业务协议。
- 默认自动搜索标记为可选；明确请求图片标记为必需。明确图片要求优先于自动策略。
- Vue 生成及修复沿用同一策略，只有必需素材触发原有两次提醒和 `VUE_IMAGE_USAGE_MISSING`。
- 同步生成系统提示，避免提示仍然要求可选素材强制写入；审查提示如引用图片策略也同步核对。
- 兼容缺少策略字段的旧上下文：保持旧的非空素材检查，避免旧检查点被无条件放行。
- 保留原有成功写入 URL 的有限判定，不能把它解释为图片确实可见、可加载或完整渲染验证。
- 不增加工具次数、模型格式重试、正式修复次数，不改变公共 SSE 和内部工具契约。

## 回归与验收

- 新增离线回归：首次电商后台有自动搜索结果、写入文件未包含图片，也能进入原构建和审查流程。
- 明确要求配图但未使用仍在原两次提醒后失败；明确配图成功写入后继续原验证。
- 不配图需求仍不搜图；已有页面保护旧图不额外搜图；后句明确新增图片仍按原规则处理。
- 覆盖生成到修复的策略保留和旧上下文缺字段兼容。
- 执行相关测试、完整 Python pytest、compileall、uv lock --check、git diff --check；完成后按仓库约定提交中文 Conventional Commit。
- 更新 `ai-service/README.md` 和本交接中的实际验证、提交与部署状态。
