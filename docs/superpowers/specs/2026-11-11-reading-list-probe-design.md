# 固定读书清单需求的浏览器交互探针

承接第 18 节的真实续验。新 Vue 应用生成成功且静态检查实际执行，但没有自然触发修复；需要用真实页面行为判断筛选和计数，而不能由构建成功或模型 PASS 推断。

选择提取可复用的浏览器探针，不在本轮引入通用生产浏览器门禁。后者需要单独定义可信操作、页面隔离、超时、网络访问和修复证据契约。单纯重审同一份源码也不能证明交互正确。

`scripts/acceptance_reading_list_checks.mjs` 只验证“慢读书房”固定需求：三本初始未读书、添加/空白拒绝、已读切换、三种筛选，以及计数始终以总书量而非筛选结果展示。计数文案限定为“共 N 本 · 已读 M 本”。要求唯一按钮/输入框，拒绝在歧义页面任取元素；按有限实际状态轮询等待渲染。

调用者提供同源隔离 document 和 tick；探针会在页面内添加“验收新书”，所以不得对用户正在使用的页面执行。结果只含固定检查名、布尔值和数字，不输出页面正文或凭据。没有生成、模型调用、任务恢复或服务端部署入口。

Node 测试启动无调试端口的独立 Chrome，用四个手写 DOM 夹具分别验证通过、缺筛选按钮、计数不更新和筛选无效；它证明探针能发现指定反例，不是自然 Vue 生成证据。随后相同模块对新应用预览与本机部署执行零模型检查，分别保存结果。CSS 背景图、任意事件语义、所有响应式尺寸和生产自动运行均不在该探针保证中。
