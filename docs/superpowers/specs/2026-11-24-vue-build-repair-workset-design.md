# Vue 必填属性构建失败的有界修复

用户已在本轮授权实施此前建议并进行本地真实模型验收。沿当前专用分支工作，保留共享 40 次模型工具和本地 3 次修复，不修改源码默认预算。

## 已确认方案

Spring 保留可信 props 检查器现有 v1 协议，从已严格解析的 file/component/prop 生成可选 componentIssues，并通过内部 project_build 响应传递。旧三字段构建结果兼容，不从自由错误消息解析路径，不新增模型执行器。可选字段严格最多四项。

Python 仅在 Vue 的 VUE_COMPONENT_CONTRACT_FAILED 且存在有效结构化问题时读取一次原有有界源码快照，用当前安全文件清单组织 TECHNICAL_ERROR 问题，复用 repairWork 的最多三个文件、活动文件完整共同可见、三批读取后必须写入与成功写入后才能声明完成等协议。源码快照只用于清单，不整体塞给模型；componentIssues 不进入父图或公共事件。

保留未知旧网关、无结构化字段和不完整快照的原修复路径。快照工具故障及取消沿已有异常路径传播，不增加重试；完整问题只留验证和修复子图。结构化问题只是可信静态检查范围内的证据，文件清单不是写权限，Spring 仍执行沙箱检查。

在已有工作集三批读取门槛基础上，为低剩余额度预留一次最小写入：若未写入工作集请求的读取批次会用完剩余模型工具，则整批拒绝并使用原两次格式纠偏要求基于当前可见结果写入；继续拒绝按现有停滞错误终止。零额度不调用模型假装修复；通过同一严格工作集协议拒绝空完成。此新增规则仅作用工作集，不改变普通生成和旧构建修复路径。

构建、可信 props/events/anchors 和 Reviewer 全部保留。修复提示增加对象字段与生产消费契约核对，避免只修属性名；不要求扩展业务。

## 验证与边界

离线覆盖 Java 严格问题输出、内部工具契约、Python 安全路径/快照回退、硬错误启用工作集、无写入空完成/轮换读取/低额度、取消及私有字段边界，运行 Java 干净编译和相关测试、Python compileall/pytest/lock。

真实验收使用同一个持久账本、最多 60 次供应商请求，默认只进行一次新 Vue 电商后台生成与一次针对旧失败应用的正常平台修复；失败也计数，不换账本绕过上限。停止时保留失败和未测项。不手工修补用户生成工程、不调用部署。普通完整生成未触发构建错误时，只能证明生成结果，不能冒充验证了定向修复；需另用已失败应用触发实际硬契约修复。

单纯加预算会延长循环；仅补提示无法约束轮换补读；本轮采用结构化硬错误复用既有工作集，代价为 Java/Python 同步部署。模型仍可能格式错误、越界、耗尽次数或无法解决字段问题，任何通过均不代表完整浏览器功能正确。
