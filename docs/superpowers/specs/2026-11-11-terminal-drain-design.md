# 真实验收发现的终态与 checkpoint 收尾竞态

本轮用户要求继续完成真实端到端验收，并取消模型次数上限。HTML/MULTI_FILE 的真实请求可成功，但既有日志重复出现 PostgreSQL 事务清理告警。

离线门闩测试确认 `GenerationWorkflow.stream` 会在 `_execute` 完成之前投递成功/失败终态；消费者收到终态关闭流时，finally 会取消仍在图写入/清理中的任务。此时序是已复现缺陷；不能仅凭此认定所有 PostgreSQL 告警有相同根因。

采取最小变更：流边界暂存最终 completed/failed，继续等待队列结束及后台任务完成后发送。非终态事件仍实时返回，事件内容、公共 SSE 协议、发布规则及模型预算不变。清理异常仍按原行为记录，不改写业务终态。用户主动取消、真正传输断开仍沿用现有取消流程；重复取消问题需按真实复测证据另行处理。

验证：先运行成功/失败两种门闩回归确认旧代码失败，再验证修复通过和已有流式/取消测试。执行 Python 全量离线检查，重启 Python 后运行三类真实成功与取消请求，分别记录重启前后日志，不把历史通过结果改称修复后结果。
