# 静态产物模型文本流式设计

本阶段承接子图交接优先项三，先实施 HTML/MULTI_FILE 首次生成与静态修复的模型文本流式，生产恢复单独设计。

## 方案和范围

采用模型适配器的可选流式能力、请求内展示回调、完整候选单独返回。与直接把 token 作为原 content_delta 候选相比，明确展示/候选语义可防止 Spring 缓存最后一个分片；与一次引入生产恢复相比，本轮只改变当前请求的内容传输，验收边界明确。普通 generate/repair 保留，未实现流式能力的 Fake/兼容模型继续走旧接口。Vue 保持完整 JSON 响应再校验与执行工具，不增量执行或展示工具参数。

适配器使用 ChatOpenAI.astream，按顺序合并 AIMessageChunk，保留结束原因与用量并返回完整 ModelTurn；编排层仅在存在明确正常结束原因后发送完整候选。截断/过滤、无结束原因、空流与异常均不得发布候选。上下文预算与自动 LangSmith 脱敏策略沿用原调用。取消通过展示回调和任务取消中断，迭代器必须关闭；流中途失败不回退重新调用模型，避免重复费用和候选混合。

## 内部与公共协议

NDJSON 仍用 content_delta，静态流式路径增加 data.contentMode：display_delta 为展示增量，candidate 为该轮完整候选。candidate 只在完整、非截断响应通过结束检查后发送。node、sequence、requestId 不变，静态修复保留 repairCount。旧事件未标记模式时继续视为完整候选。

Spring 网关将展示增量封装成仅 Java 内部识别的展示帧，交给 SimpleTextStreamHandler 解包为原始 SSE 文本；成功终态后将最后候选封装成内部候选帧，handler 用其替换历史缓冲且不重复向前端发送整段源码。旧非流式与 Legacy 流路径不变。内部帧使用保留前缀，不传给浏览器或聊天历史。展示增量不能覆盖候选；新一轮增量开始时清除旧候选，流式 completed 没有新完整候选时失败。未知 contentMode 失败，避免误把展示当产物。

公共 SSE 没有新事件或前端状态字段；前端继续 2000 字符/80ms 展示、成功终态回源及单次预览刷新。多轮修复可能展示被淘汰草稿，最终历史仅保存成功发布候选。用户应先部署支持模式的 Java 再部署 Python，以获得实时展示。

## 验证与边界

使用模拟 AIMessageChunk 流验证首片在模型结束前可见、精确合并和结束元数据、上下文预算、自动追踪关闭、取消/异常释放流、截断与无结束原因零发布；验证 HTML/MULTI_FILE 生成和修复、Vue 完整 JSON 不走增量执行、旧模型回退。

Java HTTP 回归验证 delta 与候选分离、修复后只保存新完整候选、展示在 completed 前可见、失败/EOF 不保存历史、未知模式和缺失候选失败，以及旧协议兼容。运行 Java 干净编译和相关测试、Python 全量检查与前端既有流式测试/类型检查/构建。真实供应商、Spring/Python 联调和浏览器未执行时必须明确说明，模拟测试不代替端到端验收。

不增加生产恢复、SSE 重放、checkpoint token 级状态、长期记忆、新存储或新配置；模型节点重建恢复仍只能从既有节点 checkpoint 继续，不能续接供应商 token 流。
