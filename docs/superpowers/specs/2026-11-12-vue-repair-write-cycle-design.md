# Vue 修复批次源码集合判重（方案 A）

用户已明确选择交接第 24 节方案 A。本轮只处理正式 Vue 修复工具循环内的重复写入，不改生成、Legacy、工具预算、修复上限或浏览器验收范围。

## 触发与证据

完整批次至少有一次 file_write/file_modify 返回显式 `ok is True` 后，调用 Spring `vue_source_snapshot`。同批后续读取、修改、删除必须先执行完；单独删除或读取批次不新增扫描。调用 ID 为本阶段 prefix 加 `:source-snapshot:{ordinal}`，不加入模型工具历史，不增加模型工具计数。

复用 `vue_snapshot_fingerprint`：只有非空、明确完整、计数一致、无重复路径且每文件未截断的集合参与。比较排序后的路径及完整内容，包含文件新增/删除，不只比较一个组件。保存的唯一指纹列表属于 Vue 子图私有进度，每阶段重新初始化；条数受原工具预算约束。首次观察发生在首次成功写入批次后，不补读阶段开始基线。

已见集合再次出现（包括 A→B→A），且当前 filePlan 无待写文件、图片要求已满足时，工具循环交回原验证/强制构建/审查。否则继续，仍记录有效指纹。未知、空或截断快照不新增指纹、不触发退出；保留此前有效指纹，未来完整集合仍可与其比较。这里没有连续性推断。

## 故障与恢复

快照调用异常沿现有工具错误路径传播，不吞掉取消、鉴权或运行环境问题，不额外重试、不让模型修环境。调用前后检测协作取消，异步取消自然传播。公共事件只返回快照计数，日志只记录固定退出原因，不记录源码、路径或指纹。

沿现有 continue_loop 节点提交批次标记及指纹。execute_tool 已保存成功结果后恢复不会重复执行该写入；continue_loop 保存后恢复保留历史指纹。若扫描后尚未保存节点结果就中断，恢复可重新读取实时快照（Spring 不缓存该工具成功结果），不承诺扫描恰好一次。测试内存 checkpoint 的显式恢复不是新增生产自动恢复。

## 限制与验收

快照仍为 Spring 有界选取（24 文件、单文件 12000 字符、总 60000），不是全工程原子快照，也不证明语义进步、构建成功或交互正确。返回验证后原 REPAIR_NO_PROGRESS 可能拒绝已验过的集合；本机制不直接产生成功或该错误。额外扫描次数受成功写入批次数限制。

Fake 回归覆盖重复/A→B→A 后重建成功与失败、其他文件持续推进、增删文件、未知/截断、显式写入成功、批次边界、计划/配图、阶段隔离、取消/错误、预算和 checkpoint。自然模型及浏览器闭环继续单独记账，不用受控测试冒充。
