# 应用生成输入审核设计

用户已确认采用四类审核，普通缺失细节使用合理默认值，仅关键冲突或核心功能不明确时澄清。

## 决策与边界

对内容安全、任务范围、需求冲突和规模可行性进行审核。安全恶意请求和明显无关任务返回 REJECT；关键冲突、超大范围或需要先明确真实接口/演示功能的请求返回 CLARIFY；不影响完成明确需求的限制返回 ALLOW_WITH_WARNING；正常请求返回 ALLOW。模型输出使用严格 JSON schema，并限制原因、提示和问题数量。不改写原始提示词，不默认删减功能，不按敏感词机械拒绝。

Spring 保有业务数据和文件权限；内部生成请求补充有界近期用户需求、初始需求及项目存在标记。Python 的 input_guard 在任何 Spring 工具调用前执行审核。路由接口复用同一审核服务。审核上下文只保留有限历史并标明截断，当前提示词不能被截断；每个真实模型请求按 UTF-8 字节上界保守检查上下文预算（不是供应商精确 tokenizer），为输出预留配置额度。

基础检查拒绝空白、超长输入、异常控制字符和超预算输入。模型审核默认开启，超时或无效输出有限重试后返回 INPUT_REVIEW_UNAVAILABLE，不将技术故障误报为违规，也不绕过审核。取消必须结束审核任务，禁止后续工具执行。ALLOW_WITH_WARNING 继续原始需求；警告不能授权生成不受支持功能的静态假实现。需要改变范围时只能 CLARIFY。

## 协议与交互

生成继续使用 NDJSON node_status/failed，Spring 映射现有 SSE 文本或 business-error。审核警告适配三种类型，但不混入静态产物。澄清提示包含最多两个问题，用户通过下一条消息回答，原预览不刷新。路由失败返回结构化 error，Java 转换中文 BusinessException，创建失败不保存应用。路由通过可带审核警告；真正生成仍独立审核，不信任前端携带“已审核”标记。

## 验证

Fake Model 覆盖四种决策、空白/长输入/控制字符、否定及普通模糊需求、上下文截断、预算、无效 JSON、审核故障和取消；检查拒绝时工具调用数为零。Java 检查路由中文错误、三类警告和静态产物分离；前端继续保持窗口限额、失败保留预览及终态行为。真实审核效果需要带已知预期结果的真实模型验收，离线测试不代表真实模型准确率。
