# 删除应用同步移除精选应用设计

## 目标

用户或管理员删除应用后，精选应用列表立即不再展示该应用，避免逻辑删除后的缓存数据继续指向已不存在的应用详情。

## 方案

精选列表由 `app` 表的 `priority` 字段查询，并通过 `good_app_page` Redis 缓存保存分页结果。删除入口最终统一调用 `AppServiceImpl.removeById`，因此在该服务方法成功执行逻辑删除后清空 `good_app_page` 全部缓存键。下一次精选列表请求会重新查询数据库，自动排除逻辑删除记录。

该方案覆盖用户删除和管理员删除，不改变现有逻辑删除、聊天记录清理及权限校验行为。

前端首页删除成功后同时重新加载我的应用和精选应用列表，更新卡片、分页记录和总数，避免当前页面继续保留旧列表。删除失败不触发缓存清理。

## 验证

通过 Spring 缓存代理测试验证成功删除清空所有精选分页键、未成功删除保留缓存；执行 Java 干净编译、相关测试、前端类型检查、现有 14 项纯函数测试、生产构建和两仓库 `git diff --check`。本轮不声称真实 Redis 或浏览器端到端验收通过。
