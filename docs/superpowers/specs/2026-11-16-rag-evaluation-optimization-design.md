# RAG评估闭环及下一轮优化方案（待审阅）

日期：2026-11-16。本文提供可运行评估流程、本轮真实隔离实验和生产优化建议。评估工具已落地；单文档多块、模型提示、版本协议等生产行为尚未切换。

## 1. 推荐决策

采用“先解决版本正确性，再按证据缺口逐层优化”的路线。单文档最多两块值得继续实验，但本轮尚不满足推广门槛：精确标注证据有所增加，拒答契约仍7/8，三类型比较和状态解释仍缺证据，抽样裁判又漏掉了主要失败题。不能据回答数40/40或裁判局部满分宣称整体优化成功。

本轮交付包括：48题新诊断集、63条精确原文事实、可运行快照对照、块级指标、实际最终上下文及Ragas常见字段导出、可选语义裁判、调用预占账本、版本组合缺陷测试。旧90题和生产检索实现不变。

## 2. 阅读材料与项目适配

已读取用户提供的[Datawhale《RAG系统评估》](https://datawhalechina.github.io/all-in-rag/#/chapter6/18_system_evaluation)，并通过站点公开的[Markdown正文](https://datawhalechina.github.io/all-in-rag/chapter6/18_system_evaluation.md)核对内容。2026-11-16下载正文SHA-256为`a175b77790ea1a2b2d34dd0780852d6b67e9897fb47888284679dfd2e84d1571`。

采纳其中两项核心方法：

1. RAG三元组：上下文相关性、忠实度、答案相关性，三个维度分别观察。
2. 七步闭环：目标→数据→标准运行记录→基线→分层分析→Bad Case→回归门槛。

文章本身也指出三元组不是完整清单。本项目另加事实完整性、公开否定解释/拒答、安全、版本一致性、错误、延迟和调用成本。不把传统Precision/Recall与Ragas的ContextPrecision/ContextRecall混称；不采用统一经验阈值替代本项目基线。

本轮未安装或执行Ragas框架；已建立其常见单轮字段的导出接口，语义评审使用独立的严格JSON契约。文章中BLEU/ROUGE可作字面相似度参考，但不能证明事实正确或中文释义的语义忠实，因此不作为本项目发布门槛。

## 4. 可运行的评估流程

### 第一步：注册假设与冻结条件

先声明本轮只改变一个变量。本轮为“重排后每文档上限1块→2块”，仍总计最多3块。冻结72块正文、Embedding向量快照、Top8候选、真实BGE顺序、R1提示、字符/字节预算和问题集，选择器不读取事实标注。

后续实验还需记录供应商模型响应版本（若有）、代码哈希、数据/标注版本、随机性、运行顺序、并发、软硬件和价格版本。模型别名及签名只能支持追踪，不能保证供应商更新后的逐字复现。

### 第二步：先做无需模型的校验

执行数据源哈希、原文span、ID/问题唯一性、分组校验，以及解析、裁剪、契约测试。篡改来源、分组泄漏、错误引用、重复claim、布尔评分、缺失样本和额度耗尽均应显式失败。

### 第三步：记录同一次运行的实际输入

逐题保存检索Top8、真实重排顺序、选择和最终上下文、回答、引用、所用模型/提示签名、延迟、usage、错误和额度记录。传给裁判的是经过预算裁剪后的上下文；禁止用更完整的原文为模型回答补证。

本轮快照模式用全部公共正文的精确cosine，不经过生产Milvus。正式端到端阶段仍用现有HTTP同请求trace，核对实际文档ID、内容版本和hash；生产trace只记录白名单元数据，不为评估向普通日志添加正文。

### 第四步：分别计算三元组与工程指标

| 维度 | 当前实现/指标 | 不能推出的结论 |
|---|---|---|
| 上下文相关性 | 块级annotated Precision/Recall/MRR/AP/NDCG；必要事实span覆盖、完整题数 | qrels未穷举，不匹配不代表无关；span命中不等于语义支持 |
| 忠实度 | 回答拆claims，逐项评实际上下文支持，核对claim原文和证据quote | 原文可找到不自动证明逻辑蕴含；裁判仍需校准 |
| 答案相关性 | 匿名语义评分0/0.5/1、必要事实覆盖、是否直接回答、引用是否必要 | 回答非空或answered=true不能证明完整 |
| 拒答 | 可答误拒/不可答漏拒；服务错误单列 | 安全解释answered=true违反当前拒答契约，但不必然执行了越权 |
| 版本 | 旧任务/墓碑/重建/迟到owner/丢响应分开测试 | Milvus Strong、Fake通过或保留两代均不证明跨系统原子性 |
| 工程 | 缺失/错误、平均/P95延迟、实际usage、调用预占 | 两并发快照延迟不是生产SLO、吞吐或真实币种成本 |

Precision@k固定分母k，不足k不能用较小分母抬分；AP@k分母为全部已标注相关块数，MRR看首个相关块，Recall以全部已标注块为分母。必要事实覆盖按问题宏平均；完整证据题要求该题所有标注事实均保留。空gold的拒答题不计算IR，故障/未测不能算正确拒答，语义缺失保留null和缺失数。

### 第五步：分组、配对与人工校准

输出24个问题组及逐题两组差异，不只看全局均值。样本重跑三次按问题/组配对统计，不能当作新增独立题。本轮等距抽12题，每组12次语义评审；同一个模型担任回答者和裁判，存在自偏好，且等距样本没有覆盖主要Bad Case。

下一轮裁判校准集必须预先包含全部安全执行请求、已知漏事实题和正确的同义释义/冗余前提反例。由人工复核“模型判好但实际漏事实”和“原文span未命中但语义充分”的案例，保留裁判误差，而不是增加模型调用后只展示好看的评分。

### 第六步：归因与单变量实验

区分召回不足、排序压低、同文档配额、预算裁剪、生成漏答、引用冗余、拒答契约、标注错误和裁判错误。只有发现哪个阶段丢证据，才调整那个阶段。当前trace retrieved已经过store验证，正式诊断还需区分ANN原始候选与版本过滤后的候选。

### 第七步：门禁与持续回归

发布前全部预定样本必须完成；服务错误/缺失不能通过换分母消失。版本与撤销测试零违反；安全8题至少三轮24/24满足内部契约，公开否定解释不得新增误拒；必要事实及人工事实正确率无已知退步；引用结构零非法且关键样本来源支持通过。延迟首轮建议P95不超过同机同并发现状20%，正式SLO按负载确定。小样本过门只进入下一阶段，不等于全域安全。

## 5. 本轮真实隔离实验结果

模式：本地11文档72块→真实Embedding→精确cosine Top8→真实CUDA BGE→两种选择策略→真实DeepSeek回答。两组各48题，总共96次回答；12题两组语义评审24次，合计120次聊天调用；Embedding4批、120个输入。无生产索引写入。

| 指标 | 现状：每文档1块 | 候选：每文档最多2块 |
|---|---:|---:|
| 回答可答题 | 40/40 | 40/40 |
| 拒答契约通过 | 7/8 | 7/8 |
| Top8必要证据宏覆盖 | 99.375% | 同一批候选 |
| 最终必要证据宏覆盖 | 90.208% | 93.125% |
| 最终完整证据题 | 33/40 | 35/40 |
| 重排Top3完整证据题 | 35/40 | 同一批顺序 |
| 回答错误/缺失 | 0/0 | 0/0 |
| 有效语义评审 | 12/12计划 | 11/12计划，1次无效 |
| 回答均值/P95 | 1025/1396ms | 1002/1370ms |

按当前标注，3题证据改善（002/006/007）、1题降低（032），回答/拒答数量没有变化。预算裁剪阶段本轮没有额外证据损失，不能把主要问题归咎于3000字符预算。

语义抽样有效评审中的忠实度为24/24、17/17条claim支持，相关性与必要事实覆盖均为1；**这不是全量满分**。两组有效分母不同，抽样漏掉了002/006/007/021/026/029/030/032等关键题，1次评审无效未重试，结论仅限这些通过结构校验的评审记录。不能用于抵消全量的拒答或事实缺口。

聊天usage合计输入86991、输出9975、总计96966 token；费用单价未冻结，不给出虚构人民币金额。Embedding另计，不混入聊天token。完整结果、usage及向量保存在忽略目录`tmp/rag-evaluation-20261116/live-snapshot/`。

## 6. 三种可选路线

| 路线 | 收益 | 代价与边界 | 推荐 |
|---|---|---|---|
| A 仅放宽同文档到2块 | 改动小，本轮证据+2.917个百分点 | 三事实题仍不足；可能挤掉互补文档；安全失败未解 | 保留实验候选，不直接上线 |
| B 版本先行+有界证据组合+定向召回 | 同时解决可维护性和本轮可定位缺口 | 需Java/Python版本迁移、证据标注与隔离验收，分步实施 | 推荐 |
| C 直接Hybrid/查询分解/Agentic RAG | 可能改善别名、多意图、错误码召回 | 增加依赖、调用、延迟和归因难度，不解决版本冲突 | 证据支持后再评，不作为第一步 |

### 推荐路线B的实施包

**B0：版本正确性，独立于质量实验。** 分离contentRevision/indexRevision/activationRevision/buildRevision和attempt；新索引用不可变候选，重试复用版本身份；保留旧servingRevision及历史原文登记。禁用墓碑作用于原激活代际，启用走新激活，不能手工删墓碑。全库发布以Spring条件仲裁为权威，快照过期/丢响应/alias双写必须对账；默认阻止空构建覆盖非空库。详见11月13日方案，迁移需独立设计与回滚演练。

**B1：必要证据组合。** 先实验允许同文档最多3块但仍总计3块，与1/2块比较；然后尝试有界父章节/相邻块扩展。仅当候选满足问题子意图、来源同内容/索引代际且不突破字节预算时扩展；选择时只能使用问题和检索信息，不能偷读评测gold事实。三块来源各自保留身份，不能把拼接正文伪装成单一旧chunk引用。分数和关键词不保证语义充分。

**B2：标题与召回。** 标题路径加入Embedding/重排输入是独立变量，记录输入版本并构建隔离候选；Top8/16/24比较使用相同final预算。030的排名11为扩召回提供动机，但021/029说明不能把所有问题归结为TopK太小。只有此后仍有词汇缺口，才加BM25+RRF。

**B3：回答与拒答。** 保留公开权限解释可答，对实际执行越权动作强制满足当前拒答契约。先用固定上下文复测026及成对合法否定题，比较更清楚的提示与独立意图门禁；前者成本低但有随机性，后者需要更多分类边界与误拒测试。不能仅按“管理员/不能”等词硬拒答，不未经测试叠加历史E1。

**B4：评估治理。** 人工复核v2事实必要性及等价证据，另建v2.1；校准裁判、补重点失败抽样；建立新增问题的独立盲测。每次只推进一个变量，以同请求轨迹和逐题结果决定推广。

## 8. 审阅建议

建议批准路线B，并将生产工作拆成“版本协议修复”和“证据组合/召回”两次独立发布。先复核本轮标注疑义和026拒答契约，再决定两块候选是否继续扩为三块或父章节方案。不同实现对引用协议、预算与召回多样性的影响应在各自生产改动前确认。

本轮不建议仅凭抽样裁判满分、answered40/40或覆盖率提高直接上线。优化收益已有局部真实证据，推广结论仍需标注复核、重复试验及生产同请求验收。
