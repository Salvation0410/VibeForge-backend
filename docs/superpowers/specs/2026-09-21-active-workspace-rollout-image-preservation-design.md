# 当前运行分支接入与图片保留设计

## 背景与证据

当前浏览器实际运行的是后端、前端 `dev` 工作区，而上一轮已验证的 HTML 安全发布与流式性能优化仍位于隔离 worktree。

事故应用 `459466135980023808` 的现有 `index.html` 具有以下确定性问题：

- 文件以自然语言说明和 ````html` 围栏开头，说明旧解析器仍在原样保存模型响应。
- 文件包含一个 `<script>`，但不存在 `</script>` 和 `</html>`，属于截断产物。
- 图片数据仍存在于 JavaScript 中，但图片节点依赖脚本动态生成；脚本截断后不会渲染。
- 当前前端仍逐 SSE 分片更新完整代码文本，并在生成期间多次刷新预览，容易触发 Chrome 页面无响应。

因此，本轮不是重新设计生成架构，而是把已经验证的安全链路接入实际运行分支，并补充“图片不可丢失”的优化约束。

## 目标

1. 当前运行的后端拒绝自然语言前缀、Markdown 残留和截断 HTML，不再覆盖上一成功版本。
2. 当前运行的前端不再逐分片渲染完整源码，生成开始不刷新预览，成功后只刷新一次。
3. 二次优化必须保留现有图片、图片 URL、CSS 背景图和媒体数据，不得替换为随机图或占位图。
4. 移除页面上的冗余生成提示，只保留紧凑进度和停止操作。
5. 保留当前两个仓库中的用户未提交修改，不修改 `projects/`，不自动修复事故应用。

## 方案

### 运行代码对齐

以已验证的后端和前端隔离分支为来源，将任务相关提交接入当前 `dev` 工作区。接入前分别保存工作区差异，接入后逐项确认用户修改仍存在：

- 后端保留 `AppServiceImpl.java` 和既有文档修改。
- 前端保留 `AppChatView.vue` 中用户自定义优化文案修改的意图，并保留 `package-lock.json`。
- 不暂存或提交 `projects/`。

发生重叠时按行为合并，不以覆盖文件方式处理。

### HTML 发布边界

模型结果只接受唯一闭合 HTML 代码块或首尾完整的纯 HTML 文档。解析、确定性校验和浏览器烟测全部通过后，才写入不可变 release 并切换 `.current`。

下列内容必须拒绝并保留旧版：

- HTML 前后存在自然语言或 Markdown 围栏残留。
- 缺少 `</script>`、`</body>`、`</html>` 等闭合结构。
- JavaScript/CSS 词法不完整。
- 浏览器烟测出现脚本异常、永久空白、永久 skeleton 或顶层跳转。
- 模型因长度限制结束。

### 图片保留规则

HTML、MULTI_FILE、VUE_PROJECT 三种优化提示均增加媒体保护约束：

- 保留现有 `<img>`、`picture/source`、CSS `background-image`、内联 data URL、对象存储 URL 和业务媒体字段。
- 不得删除图片，不得将原图片替换为 `picsum.photos` 等随机图片、占位图片或无关外链。
- 不得为了视觉统一清空相册、封面或背景图数据。
- 允许调整尺寸、裁剪方式、响应式布局、懒加载和加载失败样式。
- 若原图片无法访问，只能保留原引用并提供失败状态，不能伪造替代内容。

### 前端生成体验

SSE 分片只进入非响应式计数器，每 80ms 更新一次字符数和耗时，不把完整生成源码写入 Vue 响应式 DOM。

生成期间：

- 保留上一版 iframe/srcdoc。
- 不触发预览刷新。
- 自动滚动最多每 200ms 一次，用户向上滚动后暂停跟随。
- 提供“停止生成”按钮。
- 不显示“AI 正在持续生成代码和说明，请稍候”等冗余顶部提示。

发布成功后只刷新一次；失败、取消和截断均不刷新。

### 事故应用处理

本轮不会直接改写应用 `459466135980023808`。代码接入并验证后，该应用可通过管理员恢复接口先执行 dry-run；只有人工确认候选 HTML 完整且图片引用正确后，才显式提交恢复。

## 验证

后端验证覆盖：严格解析、HTML 校验、不可变发布、浏览器烟测、Legacy/LangGraph 发布终态、业务 SSE 错误和预算保护。

前端验证覆盖：优化提示模板、10,000 分片进度缓冲、停止生成、单次预览刷新、类型检查和生产构建。

额外增加提示词断言，确认三种生成类型均包含图片保留约束，并确认 HTML 模板禁止自然语言前缀和随机图片替换。

最后检查：

- 当前后端工作区仅保留原有用户修改和本轮任务修改。
- 当前前端工作区保留原有 `package-lock.json` 修改。
- 运行进程的命令行和 classpath 指向当前合并后的工作区构建。
- 不声称真实双服务验收通过，除非实际启动并完成浏览器验证。

## 回滚

代码接入以独立提交完成，可以按后端和前端分别回滚。产物发布使用不可变 release；新版本验证失败时 `.current` 不变，已发布版本可通过受控恢复流程切换，不直接覆盖历史文件。
