# 可回退的客服单文档块配额

## 授权与问题

第十三轮已提出“默认 cap1、可回退的 cap2 配额开关，补多块来源测试，再单列真实回答额度”。用户随后要求“继续执行下一轮优化”，本轮据此实施该路线，不重复申请相同方案许可。沿用当前 `dev` 工作区，不迁移或收走用户已有修改；后端与前端各自提交。

历史离线证据支持 cap2：审后公共事实完整支持 106/130 对 116/130，完整证据题 67/81 对 72/81，仍有 14 项事实支持不足；cap2 挤掉 59 个文档出现次数。上述是第十三轮代理证据结论，不能充当本轮模型答案质量或人工验收结果。

## 方案选择

采用有界数值开关：`AI_SERVICE_RAG_DOCUMENT_CHUNK_LIMIT`，默认 1，仅允许整数 1/2；启动时读取，改为 1 并重启即可回退。它保留已验证的基线，并为单变量真实对照准备正式路径。

直接把常量改为 2 虽改动少，但缺少独立回退入口；按题自适应配额会加入尚未验证的策略变量。本轮不采用这两种方案。不开启本地或生产 cap2，不修改真实 `.env`、Top8、重排器、阈值、提示、语料或供应商预算。

## 选择与预算

`CustomerServiceRagService` 固定请求级配额，在活动版本过滤、块去重及重排/阈值之后，由 `_select_documents` 按现有稳定顺序取块。同文档最多配置数量，最终最多 `min(rag_final_top_k, 3)` 块；同文档第二块仍占总名额。第三块不能绕过 cap2，其他文档可在尚有名额时补位。

默认 cap1 的选块、候选顺序和主要诊断原因保持兼容；cap1 超额沿用 `duplicate_document`，cap2 超额使用 `document_chunk_limit`，总名额耗尽为 `top_k`。不新增正文去重、邻块扩展或失败后的重新检索。禁用重排及故障降级沿原候选顺序应用同一配置，原阈值失败关闭逻辑不变。

字符 1200/块、3000 总量及实际 JSON 字节预算继续在选择后执行。引用只允许来自最终实际上下文中的唯一 chunkId，按模型引用顺序输出，保留各块原文档身份、版本、locator 和摘要。旧版本、不活动、重复块或未知引用仍拒绝，不把同文档身份当成放行依据。

诊断 `configFingerprint` 增加 `documentChunkLimit`，只记录固定数值；不新增问题、正文或答案日志。原固定 cap1 的 `rag_rerank_experiment` 和 `rag_snapshot_experiment` 在真实入口明确拒绝配置 cap2，避免旧实验报告声称 cap1 却实际执行 cap2；不改变旧授权账本。固定历史上下文的拒答实验无选择过程，无需改变。

## 三端契约与测试

现有 Python/Spring/前端都用最多三项来源数组和 chunkId，支持同文档不同块；本轮只按测试暴露的真实缺陷决定是否改 wire，预期不改 schema。

Python 用 Fake Model 覆盖默认/回退 cap1、cap2 稳定排序、同文档第三块/总上限、字符/字节预算、阈值、禁用/降级、引用反向顺序、重复/未知引用和旧版本过滤，核对环境变量 1/2 与非法值，以及诊断配额。用上轮 90 题的冻结候选分别走正式服务 cap1/cap2，与上轮已存上下文逐字比较，Fake Model 仅返回固定文本及真实块引用，不能产生新答案质量成绩。

Java 新测试通过本地 HTTP 替身、真实 `CustomerServiceAiClient` 与真实回答 Service、Mock Mapper，验证同文档两块和另一文档的三来源顺序、重复/旧版本/身份不符/越界块拒绝，以及超过三项由客户端拒绝。前端新独立测试文件验证同文档两块保留、按 chunkId 去重、引用顺序、三项上限与摘要边界，保留用户现有测试文件。

本轮不调用真实模型/Embedding/BGE、不写索引，不把单元及本地 HTTP 替身称为真实双服务或浏览器验收。新增真实答案对照需要单列额度；人工验收及支付候选发布仍待办。
