# 社区发帖与互动规范【推荐规范】

## 分享作品【推荐规范】

标题说明作品名称和用途，正文介绍目标用户、主要功能、生成类型、已验证效果和已知限制。附上可公开访问的部署链接和必要截图；不要把仅能自己访问的预览地址当作所有人可用链接。说明示例数据与真实服务的区别，避免读者以为已接入付款或业务数据库。

## 求助模板【推荐规范】

推荐按“我想完成什么—在哪里操作—预期结果—实际结果—复现步骤—尝试过的办法”描述问题。例如：“在 Vue 应用页生成成功后点击部署，期望打开页面，但链接显示空白；刷新仍失败；附时间、错误摘要和已脱敏截图。”错误描述只提供必要信息，不包含 API Key、密码、Cookie、OSS 签名链接或私人数据库资料。

## 标签与图片【推荐规范】

选择最贴近主题的有效标签，标题避免堆砌无关关键词。图片应帮助理解问题，标注关键区域，删除重复截图，遵守当前 9 张图片上限。提交前预览正文、确认链接可访问并检查隐私信息。标签建议不意味着系统能自动判断或自动修复错误分类。

## 评论与讨论【推荐规范】

围绕问题给出操作步骤、依据和适用条件，不用攻击、刷屏或重复广告替代讨论。回复具体评论时使用回复入口，便于识别对象。若方案仅适用于某类生成工程，说明 HTML、多文件或 Vue 范围；不能把其他平台的行为说成智创平台当前支持。

## 审核与发布边界【当前功能与推荐规范】

新帖需审核通过才进入广场，这是当前功能。清楚标题、完整复现步骤、合法素材和脱敏内容是推荐方式，不是保证审核通过的自动规则。当前没有从代码可验证的审核时间承诺，也不能承诺“按模板发帖一定通过”。拒绝公开敏感信息或侵权素材是写作规范，不应虚构自动审查能力。

## 常见问法

“求助怎么写清楚”“分享作品写什么”“发帖必须用模板吗”“审核多久保证通过”“怎么避免截图泄露信息”“评论回复怎么提建议”。发布和审核实际规则见 08。
