# HTML、MULTI_FILE 与 VUE_PROJECT 使用指南【当前功能与推荐规范】

## 类型如何确定【当前功能】

平台支持 HTML、MULTI_FILE、VUE_PROJECT 三种代码生成分支。创建应用时由系统根据初始需求自动选择并保存类型；已有应用沿其生成类型继续生成。描述里可以明确希望的工程结构，但不能保证一句关键词必然选中某类型，也不能承诺当前界面提供手动切换。

## HTML 单文件【当前功能与推荐规范】

HTML 分支要求完整 HTML 文档，可以在同一文件内包含页面样式和脚本。适合范围清楚的单页展示、活动页或简单工具原型。优化和修改后仍应返回完整文档，不能只给差异片段或省略未修改内容。页面发布前存在解析、确定性校验及浏览器运行检查；失败不应被当成新版本成功。使用建议：一个主页面、少量交互时优先描述清楚内容，不强求大型工程结构。

## MULTI_FILE 多文件【当前功能与推荐规范】

MULTI_FILE 分支将 HTML、CSS、JavaScript 等拆成文件，适合需要区分结构、样式和脚本的静态站点。它不等于 Vue 工程，也不自动提供后端数据库。输出必须包括完整必要文件，并保持文件间资源引用一致。使用建议：提出各页面关系与资源路径要求，修改时要求保留所有必要文件，不只替换一个孤立片段。

## VUE_PROJECT Vue 工程【当前功能与推荐规范】

VUE_PROJECT 分支生成 Vue 项目结构，通过文件工具和项目构建完成检查，适合组件较多、页面关系较复杂的前端工程。成功部署使用构建产物，源码下载则用于后续开发。项目依赖或路由错误可能造成构建失败，不能因为已写入文件就视为完成。使用建议：列清页面、组件、导航与状态，减少一次引入无关依赖。

## 类型边界与完整性【当前功能】

三类生成都需要保留原有功能、文字、图片和操作方式，不应输出残缺结果或额外解释。HTML 和 MULTI_FILE 有严格解析与活动版本发布检查，Vue 有工程构建检查；这些检查不能代替人工验证真实业务。请求“新增真实登录或支付”仍需要确认业务后端和服务接入，类型名称本身不代表具备这些能力。
