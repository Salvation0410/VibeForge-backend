## 每项操作细则

1. 打开应用聊天页面，读取当前预览。保存目标四属性、页面固定文字、全部图片 src/alt/加载情况和基线源码摘要。确认 `#edit-target` 唯一。
2. 点击计数按钮到 1，点击“可视化编辑”，点击标题，选择对应属性并填写唯一目标值。确认原有需求以当前产物为基线；只点一次“应用修改”。
3. 生成中观察原生 SSE 和旧 iframe，记录账本。成功场景等待真实终态；取消场景在输入审核后的生成调用已预占时点击“停止生成”，等任务确认，不能仅凭 STOPPING 判定成功。
4. 成功核对新预览目标属性及其他保持项、一次刷新、计数功能。失败/取消核对零刷新和原 document/计数；静态产物通过 Spring `artifact_context` 比较，Vue通过 `vue_source_snapshot` 报告实际变化。
5. 将唯一终态与显式任务查询、供应商审查证据和预算交叉核对。保存截图并人工查看布局与图片，记录未覆盖项。

## 结果判定与范围

结果只使用“通过 / 失败 / 未触发 / 未执行 / 执行受阻”。脚本出错时先保留已提交标记，查询任务和账本，不能盲目重跑。失败用例不因旧产物保留而改记成功；取消前生成已完成则记未命中取消窗口。

本轮不伪造质量审查失败、不注入合成 SSE，不将离线竞态测试算作真实端到端。不默认测试公网部署、从零 Vue 生成、所有 DOM 定位、跨标签并发或恢复；这些需独立测试条件与额度。结果与遗留问题补充到 `doc/generation-structured-edit-acceptance-handoff.md`。

新增受控故障用例 F01：HTML 生成中点击停止，测试代理仅去掉停止 HTTP 的 Cookie，透传真实 Spring 响应。预期停止返回 40100、原 SSE 继续、任务最终 SUCCEEDED、页面因已请求停止而不自动刷新；实际通过，服务端源码更新、原 iframe 仍为旧版。这不是自然网络失败，也不是 Fake 响应；不能宣称取消成功或服务端没有副作用。

新增真实 API 边界用例 F02-H/M/V：每类分别测试匿名生成、匿名停止、已登录的非法 editIntent 属性。最终 9 项返回预期 40100/40000、供应商调用 0；匿名生成及参数异常的 SSE 为 business-error 后接 done，不把这个结束标记当成业务成功。早期夹具曾误混匿名 Cookie 并触发 42900，原报告保留，分离会话且等待正常限流窗口后重测通过；未重置 Redis 或关闭限流。

O03 发现的终态提前投递已修复：Python 等图与 checkpoint 收尾结束后才向下游发送终态，普通分片不延迟。修复后 10 个真实请求的独立日志中原两种 PostgreSQL 清理告警及连接丢弃均为 0，ready/checkpoint=true；这只是本轮样本结果，不证明任意并发/反复取消均无异常。

O01 的自然 REPAIR→PASS 证据仍为上一轮；本轮没有自然触发 REPAIR_NO_PROGRESS，O02 保持未覆盖。从零生成 Vue、公网部署、下载、跨标签并发、恢复与全部停止失败时序不在本轮通过结论中。
